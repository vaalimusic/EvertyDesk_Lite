Оптимизации по приоритету

1
Async MediaCodec — убрать polling сейчас client
Переключить VideoDecoder на callback-режим. Кадр рендерится в onOutputBufferAvailable без ожидания. Убирает до 43ms overhead polling из sync-цикла.
▼ −30–43ms decode latency  ·  Rust-поток освобождается мгновенно
2
Resolution negotiation — телефон диктует разрешение следующий client + host
Клиент читает свой экран, шлёт хосту MaxResolution (например 1920×1080). Хост даунскейлит перед энкодом. Меньше пикселей = меньше данных на всём пути.
Сейчас
2560×1440
3 686 400 пикселей · 43 KB/кадр · 4.1 Mbps
После
1920×1080
2 073 600 пикселей · 24 KB/кадр · 2.3 Mbps
▼ −44% пикселей  ·  −44% encode time  ·  −44% сеть  ·  −44% decode
3
PerfStats overlay — метрики на экране телефона сейчас client
Singleton с FPS decoded, received kbps, jitter ms. Overlay-строка поверх видео в hw-режиме. Нужен чтобы видеть реальные цифры до и после каждой оптимизации.
→ Наша "линейка" для измерения всех остальных улучшений
4
NVENC quality 70% + zerolatency tune следующий host
Для realtime-стриминга quality=100% избыточно. 70% — субъективно неотличимо, но encode_avg падает с 8ms до ~5ms, пики срезаются. Добавить b-frames=0 и lookahead=0.
▼ −3ms encode  ·  −15% bitrate при том же качестве
5
SurfaceTexture.setDefaultBufferSize() + TextureView transform сейчас client
Когда onDimensionsAvailable даёт реальные размеры — сразу вызвать st.setDefaultBufferSize(w, h). Убирает возможный re-allocation буфера на первом кадре.
→ Убирает возможный first-frame glitch
6
FrameQueue jitter buffer = 0 для LAN следующий host
Текущий adaptive jitter buffer добавляет буфер даже на LAN с 1ms jitter. Если клиент сигналит "LAN" через IP-сравнение — выключить буфер совсем.
▼ −5–15ms jitter buffer latency на LAN

Singleton: fps, decode_ms, jitter_ms, rx_kbps. Overlay на экране. Измеряем до/после.

setDefaultBufferSize(w,h) при onDimensionsAvailable. Устраняет first-frame glitch.
