# EvertyGUI — стандарт интерфейса EvertyDesk

> Единый строгий стандарт оформления. Цель — чтобы любой новый экран
> выглядел частью продукта без раздумий, а развитие UI шло быстро и
> предсказуемо. Реализация стандарта живёт в `src/theme.rs`.

---

## 0. Золотое правило

**Никогда не пиши `Color32::from_rgb(...)` в UI-коде.**
Любой цвет берётся из палитры, любой размер шрифта — из шкалы, любой отступ —
из шкалы, любой радиус — из шкалы. Хардкод RGB допустим **только** внутри
`src/theme.rs` (определения палитр).

Почему: один источник правды → темы (тёмная/светлая) работают автоматически,
рефакторинг палитры не ломает экраны, новый разработчик не изобретает цвета.

```rust
// ❌ НЕЛЬЗЯ
ui.label(egui::RichText::new("Заголовок").color(egui::Color32::from_rgb(0x13,0x17,0x21)));

// ✅ НАДО
let t = crate::theme::palette();
ui.label(egui::RichText::new("Заголовок").color(t.text));
// или ещё лучше — типографический хелпер:
ui.label(crate::theme::h2("Заголовок"));
```

## 1. Цвет — семантические токены

Берутся через `crate::theme::palette()` (дёшево, `Copy`). Никогда не по «виду»
цвета — только по **смыслу**.

### Поверхности (слои глубины снизу вверх)
| Токен | Назначение |
|---|---|
| `bg` | фон приложения, центральная область, фон панелей |
| `surface` | карты, окна, сайдбар |
| `surface_raised` | приподнятое: hover, активные чипы, лого-плитка |
| `surface_sunken` | утопленное: поля ввода, контейнеры лога/кода, рельсы |

### Границы
| Токен | Назначение |
|---|---|
| `border` | обычные рамки карт, разделители |
| `border_strong` | акцентированные рамки: hover, фокус контейнера |

### Текст (по иерархии)
| Токен | Назначение |
|---|---|
| `text` | основной текст, заголовки |
| `text_weak` | вторичный текст, неактивные пункты меню |
| `text_muted` | подписи, метки полей, плейсхолдеры |

### Акцент (фирменный зелёный)
| Токен | Назначение |
|---|---|
| `accent` | основное действие, активный пункт, фокус, ссылки |
| `accent_hover` | наведение на акцентный элемент |
| `accent_active` | нажатие |
| `accent_fg` | текст/иконка **поверх** заливки `accent` |

### Статусы
| Токен | Назначение |
|---|---|
| `success` | успех, VM запущена, онлайн |
| `warning` | предупреждение, требует внимания |
| `danger` | ошибка, разрушающее действие, оффлайн |
| `info` | нейтральная информация |

**Бейджи/подложки**: не заливай статус-цветом на 100%. Используй
`theme::tint(color, 0.16)` для подложки + чистый цвет для текста, либо готовый
`theme::badge(ui, text, color)`.

## 2. Типографика

Шкала из 8 ступеней (`theme::font::*`). Больше ступеней не вводить.

| Константа | pt | Назначение | Хелпер |
|---|---|---|---|
| `DISPLAY` | 28 | hero-заголовок экрана | — |
| `H1` | 22 | заголовок раздела | `theme::h1()` |
| `H2` | 18 | заголовок карты | `theme::h2()` |
| `H3` | 15 | подзаголовок, strong-лейбл | `theme::h3()` |
| `BODY` | 14 | основной текст, кнопки | `theme::body()` |
| `SMALL` | 13 | вторичный текст | `theme::weak()` |
| `CAPTION` | 12 | метки полей, подписи | `theme::caption()` |
| `MICRO` | 11 | бейджи, счётчики | — |

Правила:
- Заголовки — `.strong()`, основной/вторичный текст — обычный вес.
- На один экран — один `DISPLAY`/`H1`. Не дублировать крупные заголовки.
- Цвет заголовка всегда `text`, вторичного — `text_weak`/`text_muted`.

```rust
ui.label(crate::theme::h1("Виртуальные машины"));
ui.label(crate::theme::caption("Провайдер"));
ui.label(crate::theme::body("Ubuntu Server 24.04"));
```

## 3. Отступы и ритм

Шкала `theme::space::*` (кратна 2/4). Произвольные числа (7.0, 13.0, 18.0) — нельзя.

| Константа | px | Типичное применение |
|---|---|---|
| `XXS` | 2 | микро-зазор внутри строки |
| `XS` | 4 | между связанными лейблами |
| `SM` | 8 | между пунктами списка/кнопками |
| `MD` | 12 | между элементами формы, item_spacing |
| `LG` | 16 | внутренний паддинг карты, между карт |
| `XL` | 24 | между секциями |
| `XXL` | 32 | крупные отбивки, hero |

```rust
ui.add_space(crate::theme::space::LG);
```

Глобальный `item_spacing`/`button_padding` уже выставлен в `theme::apply_palette`
— не переопределять локально без причины.

---

## 4. Радиусы

`theme::radius::*`. Соответствие размеру элемента:

| Константа | px | Применение |
|---|---|---|
| `SM` | 8 | бейджи, чипы |
| `MD` | 10 | кнопки, поля ввода |
| `LG` | 12 | секции |
| `XL` | 14 | карты, окна |

Не смешивать радиусы внутри одного компонента.

## 5. Глубина (elevation)

Глубина выражается **слоем поверхности + тенью**, а не яркими бордерами.
- Плоский контент: `bg` → элементы на `surface`.
- Поднятый (меню, попап, окно): автоматически получает тень из visuals.
- Hover интерактивного элемента: лёгкая примесь акцента (уже в стиле виджетов).

Тени настраиваются централизованно в `apply_palette` (`window_shadow`,
`popup_shadow`). Вручную рисовать тени не нужно.

## 6. Компоненты

### Карта
```rust
crate::theme::card().show(ui, |ui| {
    ui.label(crate::theme::h2("Заголовок карты"));
    ui.add_space(crate::theme::space::SM);
    ui.label(crate::theme::weak("Описание"));
});
```
`surface` + `border` + радиус `XL` + паддинг `LG`. Для утопленных блоков
(лог, код, поле) — `theme::sunken()`.

### Кнопки
- **Первичное действие** (одно на экран/секцию): заливка `accent`, текст `accent_fg`.
- **Вторичное**: стандартный egui-`Button` (берёт стиль виджетов автоматически).
- **Опасное** (удалить, hard-stop): текст/рамка `danger`, заливку только при подтверждении.

### Поля ввода
Фон `surface_sunken`, рамка `border` → `accent` при фокусе (через стиль виджетов).
Метка над полем — `theme::caption()`.

### Бейдж статуса
```rust
let t = crate::theme::palette();
crate::theme::badge(ui, "● Running", t.success);
crate::theme::badge(ui, "Offline",   t.danger);
```

### Навигация (сайдбар)
- Активный пункт: иконка `accent`, текст `text`, подложка `surface_raised`.
- Неактивный: иконка/текст `text_weak`, без подложки.
- Hover: подложка `surface_raised` + рамка `border_strong`.

## 7. Темы

Две темы: **тёмная Pro** (по умолчанию) и **светлая премиум**. Переключатель —
Настройки → Общие. Тема сохраняется в `config.ui.theme_mode`.

- Применение: `theme::apply(ctx, mode)` — настраивает egui Visuals/Style и
  обновляет глобальную палитру.
- Любой экран, использующий **только токены**, поддерживает обе темы без
  дополнительного кода. Это и есть критерий приёмки нового UI.

## 8. Чек-лист для нового экрана / PR

- [ ] Нет ни одного `Color32::from_rgb(...)` вне `theme.rs`.
- [ ] Все размеры шрифта — из `theme::font::*` (или хелперы `h1/h2/body/...`).
- [ ] Все отступы — из `theme::space::*`.
- [ ] Все радиусы — из `theme::radius::*`.
- [ ] Карты через `theme::card()`, утопленные блоки через `theme::sunken()`.
- [ ] Статусы — семантическими токенами (`success`/`warning`/`danger`/`info`),
      бейджи через `theme::badge()` / `theme::tint()`.
- [ ] Экран проверен в **обеих** темах: текст читаем, нет «светлых пятен» на тёмной.
- [ ] Один `DISPLAY`/`H1` на экран.

---

## 9. Как расширять стандарт

1. Новый цвет нужен только если у него **новый смысл** — добавь токен в `Palette`
   (обе темы), а не локальный RGB.
2. Новый повторяющийся блок — оформи хелпером в `theme.rs` (как `card`, `badge`),
   а не копируй разметку.
3. Меняешь палитру/шкалу — меняешь в одном месте, весь UI обновляется.
4. Любое отступление от стандарта документируй здесь же с обоснованием.
