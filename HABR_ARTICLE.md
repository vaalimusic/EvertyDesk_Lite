# EvertyDesk Lite: как мы делаем простой Rust + egui клиент удаленного доступа

Иногда удаленный доступ нужен без большого комбайна, сложной установки и десятков настроек. Открыл приложение, ввел ID удаленного компьютера, при необходимости пароль или подтвердил доступ на удаленной стороне, увидел рабочий стол и начал работать.

Так появилась идея EvertyDesk Lite: минимального клиента удаленного доступа на Rust и egui, который можно собрать и запускать на разных платформах, включая Windows и Linux-дистрибутивы вроде Astra Linux.

Серверная точка подключения проекта: `https://desk.everty.ru`.

## Зачем мы это сделали

У классических клиентов удаленного доступа часто есть две крайности.

Первая: все работает, но приложение большое, зависимостей много, интерфейс перегружен, а кастомизировать продукт под свою инфраструктуру сложно.

Вторая: минимальный клиент есть, но он слишком игрушечный: подключение есть, а нормального ввода мыши, клавиатуры, отображения курсора, статуса соединения и диагностики нет.

EvertyDesk Lite занимает середину: мы оставляем только то, что нужно для рабочего подключения, но делаем это аккуратно:

- понятный интерфейс;
- отдельное окно удаленного рабочего стола;
- подключение по ID;
- поддержка пароля и сценария подтверждения на удаленной стороне;
- ввод мыши и клавиатуры;
- отображение удаленного курсора;
- автоподстройка обновления картинки;
- лог событий для диагностики;
- настройки сервера уже зашиты под инфраструктуру EvertyDesk.

Главная цель: сделать клиент, который легко объяснить, легко собрать, легко запустить и легко развивать.

## Почему Rust

Для клиента удаленного доступа важны стабильность, контроль над памятью, переносимость и нормальная работа с сетевым кодом. Rust хорошо ложится на эту задачу.

Что дает Rust в таком проекте:

- безопасная работа с памятью без сборщика мусора;
- хорошая производительность;
- удобная сборка в один исполняемый файл;
- нормальная кроссплатформенность;
- строгая типизация, которая помогает не сломать протокол при развитии клиента.

Для удаленного доступа это особенно важно: клиент постоянно работает с сетью, бинарными сообщениями протокола, изображением, вводом мыши и клавиатуры. Ошибки в таких местах быстро превращаются в зависания, утечки или непредсказуемое поведение.

## Почему egui

Для интерфейса мы выбрали egui через eframe.

Причина простая: нам нужен не тяжелый desktop-фреймворк, а быстрый, переносимый и достаточно гибкий UI. egui позволяет быстро собрать рабочий интерфейс без отдельного webview, браузера внутри приложения и сложной инфраструктуры фронтенда.

В EvertyDesk Lite интерфейс специально остается простым:

- главное окно для подключения;
- отдельное окно удаленного экрана;
- минимум кнопок;
- управление частотой обновления;
- статус соединения;
- журнал событий.

Это не CRM, не панель аналитики и не маркетинговая витрина. Это инструмент, который должен открываться быстро и не мешать работать.

## Что уже умеет клиент

Текущая версия EvertyDesk Lite уже умеет подключаться к удаленному ID через инфраструктуру EvertyDesk и работать как минимальный remote desktop клиент.

Основные возможности:

- подключение к ID server и relay server;
- работа с публичным ключом сервера;
- подключение к удаленному ID;
- поддержка пароля;
- поддержка сценария удаленного подтверждения без ввода пароля;
- отдельное окно удаленного рабочего стола;
- отображение изображения удаленного экрана;
- ввод мыши;
- ввод клавиатуры;
- колесо мыши;
- переключение дисплеев;
- отображение удаленного курсора;
- автоматическое обновление картинки;
- адаптация частоты обновления;
- защита от накопления старых кадров;
- лог событий для диагностики подключения;
- release-сборка одной командой.

Серверные настройки по умолчанию:

```text
API URL: https://desk.everty.ru
ID server: edesk.server1.everty.ru
Relay server: edesk.server1.everty.ru
```

## Что оказалось самым интересным

Самое интересное в таком клиенте не кнопка "Подключиться". Сложность начинается после того, как соединение уже установлено.

Нужно одновременно решить несколько задач:

- не забить сеть лишними запросами;
- не рисовать старые кадры;
- не задерживать ввод мыши;
- не ломать совместимость с RustDesk-подобным протоколом;
- не усложнить интерфейс;
- не превратить минимальный клиент в тяжелый продукт.

Например, если просто часто запрашивать скриншоты, визуально может стать даже хуже. Кадров больше, но они приходят с задержкой, UI начинает показывать прошлое, а не текущее состояние экрана.

Поэтому в клиенте появилась автоматика:

- если кадров пришло несколько, интерфейс берет самый свежий;
- старые кадры не перерисовываются;
- обычный refresh запрашивает только активный дисплей;
- движения мыши схлопываются до последнего положения;
- ручной refresh остается, но не мешает автообновлению;
- screenshot fallback используется аккуратно, без бесконечной очереди.

Это не магия, а практичная инженерия: меньше лишней работы, меньше очередей, меньше задержка.

## Совместимость с RustDesk-подходом

Мы используем RustDesk как важный ориентир по протоколу и поведению клиента, но EvertyDesk Lite не является копией большого приложения.

Идея другая: взять совместимый подход там, где это полезно, и собрать минимальный клиент под свои задачи.

В проекте есть поддержка части protobuf-сообщений, rendezvous/relay-сценария, авторизации, сообщений мыши и клавиатуры, информации о дисплеях, screenshot fallback и задел под live video.

Сейчас клиент уже практически полезен как легкий инструмент подключения. Следующий важный этап - довести live video path до стабильного состояния, чтобы изображение шло не через частые PNG-скриншоты, а через нормальные видеокадры.

## Стек

Технологический стек проекта:

- Rust;
- egui / eframe для интерфейса;
- prost для protobuf-сообщений;
- TCP transport для ID/relay взаимодействия;
- image для декодирования изображений;
- openh264 для H264-декодирования;
- zstd для распаковки данных курсора;
- serde / serde_json для конфигурации;
- sha2 и base64 для служебной криптографии и кодирования.

Проект собирается стандартно:

```powershell
cargo build --release
```

После сборки клиент можно запускать из:

```powershell
target\release\evertydesk-lite.exe
```

На Linux принцип тот же:

```bash
cargo build --release
./target/release/evertydesk-lite
```

## Почему "Lite"

Lite в названии - это не "урезанный навсегда". Это философия продукта.

Мы хотим, чтобы первая версия оставалась простой:

- без лишних экранов;
- без перегруженных настроек;
- без маркетингового интерфейса;
- без обязательной регистрации;
- без сложной установки.

При этом под капотом приложение должно расти в сторону настоящего рабочего инструмента.

## Что дальше

План развития EvertyDesk Lite:

- стабильный live video через кодеки;
- ускорение отображения картинки;
- улучшение совместимости с обычными RustDesk-хостами;
- полноценный host-режим;
- терминал для администрирования;
- безопасный запуск скриптов;
- магазин автоматизаций;
- профили подключений;
- журнал сессий;
- настройки качества и скорости;
- сборки под Windows, Linux и Astra Linux.

Отдельное направление - автоматизация. Удаленный доступ часто нужен не только чтобы "посмотреть экран", но и чтобы быстро выполнить типовые действия: проверить службу, установить агент, собрать логи, запустить диагностику, применить скрипт.

Поэтому идея магазина автоматизаций выглядит логичным продолжением: пользователь подключается к машине и может запускать проверенные сценарии без ручной рутины.

## Итог

EvertyDesk Lite - это попытка сделать удаленный доступ проще: меньше интерфейсного шума, больше практической пользы.

Мы строим клиент на Rust и egui, держим фокус на переносимости, скорости и минимализме, а серверную инфраструктуру привязываем к `desk.everty.ru`.

Проект еще развивается, но направление уже понятно: легкий клиент, совместимость с привычным remote desktop подходом, быстрый запуск, аккуратный интерфейс и будущая автоматизация поверх удаленного доступа.

Нам не нужен еще один тяжелый комбайн. Нам нужен инструмент, который просто открывается, подключается и помогает работать.
